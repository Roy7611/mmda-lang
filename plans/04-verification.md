# 04 可信性工程（怎么让"AI 写的代码"可审、可证、可回滚）

> 你担心的是对的：**上一轮没人审的代码不是实现**（`lang.rs` = `regex` + `serde`，`RecordAst.fields: Vec<String>`）。
> 本文给替代方案：**不靠读代码取信，靠可执行判据取信** —— 并明确这些判据**不能**证明什么。

## 1. 四条自动判据（每条都能一条命令复现）

> **基准声明（✔ 2026-09-26 作者纠正）**：语料是**历史逆向工程产物，语法仍在调整**，**不是基准**（[`02-parser.md`](02-parser.md) §1.1）—— 基准是 `doc/` 规范 + `errata` 已裁项，逐条落成用例。

| # | 判据 | 命令 | 失败意味着 |
| --- | --- | --- | --- |
| **P1** | **规范用例集全绿**：`doc/` 每个语法点一条正例 + `errata` 每条已裁规则一条用例，正例 0 error | `m check tests/spec/**` → `errors == 0` | 语法/规则与规范不符 |
| **P2** | **round-trip 逐字节无损**（用例 + 语料子集） | `m parse --verify-roundtrip <路径>` → `cst.text() == 源字节` | CST 丢信息（注释/空白/CRLF）→ 图形↔文本双向必坏 |
| **P3** | **反例套件**：每条硬门禁 ≥ 1 条能定位到行列的反例 | `m check tests/ui/**` → 每条 `//~ ERROR M0xxx at L:C` 全部命中 | 规则写错，或错误位置不准（= 体验坏） |
| **P4** | **语料冒烟 + 漂移报告**（**不作门禁**） | `m check <语料根> --format json` → `panic == 0`、`undiagnosed == 0`；漂移条目数只记录 | 解析器会在真实体量输入上崩 / 报错但不给位置 |

**P2 是最关键的一条**：它同时证明「这是在做语言处理，不是字符串解析」。**P4 的产出（漂移条目）正是迁移工具的输入** —— 哪些文件、哪些写法要跟着新语法改。

## 2. 用例集（唯一验收基准）

- `tests/spec/**`：**每个语法点**一条正例；`tests/ui/**`：**每条硬门禁**一条反例（内嵌 `//~ ERROR M0xxx at L:C`，见 §4）。
- 用例命名带规范出处，可回溯：`tests/spec/records/import-name-clash.m` ↔ [`../doc/lang/records.md`](../doc/lang/records.md) 头部；`tests/ui/partition/segment-overlap.m` ↔ [`../doc/design-notes.md`](../doc/design-notes.md) 范围表。
- **语法变更 = 改用例**：你在 `doc/` 改一条，我加/改用例 + 改单点表（[`02-parser.md`](02-parser.md) §3.1）；用例集进版本控制，**它就是"规范可执行化"的那一份**。
- 基线 `tests/spec/baseline.json`：`{ cases, passed, failed, roundtrip_failures }`；**`failed` 必须恒为 0**。

## 2.1 语料（**不是基准**，只做三件事）

| 用途 | 判据 | 说明 |
| --- | --- | --- |
| **冒烟** | 372 文件零 panic；**每条诊断都有位置** | 不要求 0 error —— 它是历史产物，本来就该报错 |
| **漂移报告** | 输出「写法 × 文件数」清单 + 每类给 1 个 `文件:行` 样例 | **迁移工具的输入**；只记录趋势，不设阈值 |
| **性能负载** | M6 起：全量 parse < 1 s、check < 2 s | 只作负载，不作正确性判据 |

- 语料**只读快照**进实现仓 `tests/corpus/`，附 `sha256.txt`，CI 校验 hash —— **禁止改语料让测试变绿**（包括"顺手修正"旧写法：那属于迁移，不属于回归）。

## 3. UI 测试（内嵌期望输出，仿 rustc / LLVM lit）

`.m` 用例文件里直接写期望，**改一行就回归**：

```m
record Order {
    @Ref base.Material material;   //~ ERROR M0601: @Ref 目标不存在
    tenantId missed;               //~ WARN M0402: 非组内成员写了范围
}
```

- 好处：期望与代码在同一个文件里，review 时**一眼看到**规则与反例；不需要在别处维护"期望字符串"。
- 错误码与行列是**断言的一部分** —— 防"报错但报不准"。

## 4. 快照（`insta`）

- 每份语料的 **CST 快照**（`*.snap`，纯文本、可读）随实现进仓。
- 我改一次解析器 → CI 出 **diff：哪些文件、哪个节点变了**。**你不读 Rust 代码，只读快照 diff** —— 这是替代"逐行审 AI 代码"的主要手段。
- 快照变更必须**显式接受**（`cargo insta review`），且**在提交信息里说明为什么变**。

## 5. CI 门禁（合并前必须全绿）

| 门禁 | 内容 |
| --- | --- |
| `cargo fmt --check` / `cargo clippy -D warnings` | 风格与静态问题 |
| `cargo test --workspace` | 单测 + UI 测试 |
| 用例集 | P1 / P2 / P3 全绿 + 基线 `failed == 0` + 用例集 hash 校验 |
| 语料冒烟 | P4：零 panic、诊断均可定位（**漂移条目只记录，不设门禁**） |
| 快照 | 无未接受的变更 |
| 性能（M6 起） | 全量 parse / check 时间阈值 |
| 规模 | 单文件 < 500 行、单 crate < 5,000 行（超了必须在本轮说明并给出拆分计划） |
| 生成物（M4 起） | `m gen --check` 通过：生成清单与实际文件集合一致、生成物指纹与元数据一致（**被手改即 error**） |

## 6. 每轮交付物的固定格式

1. **命令 + 原始输出**（不是"我实现了 X"）；
2. 语料回归摘要（372 文件：parse / check / round-trip 三项数）；
3. 快照 diff；
4. **已知未做 / 未验证清单** —— 这一项没有就等于交付不完整。

## 7. 可审计性设计

- **公开 API ↔ 规范对照表**：每个 crate 的 `pub` 类型必须在 [`02-parser.md`](02-parser.md) §7 的对照表里能找到 `doc/` 出处；
- **可追溯**：任何"为什么要这个抽象"都能用 `git log -S` 查到引入提交与当时的用例（沿用它已有的纪律）；
- **小步提交**：一个提交一件事，提交信息带判据编号（`P1/P2/P3`），必要时可 `git revert` 单点回滚；
- **禁用**：`unwrap()` 进库代码（只在测试与 CLI 顶部）、`unsafe`（M8 的 FFI 边界除外）、未挂用例的"支持某语法"。

## 8. 这三条判据**不能**证明什么（诚实边界）

- 不能证明**语义完备**：0 error 只说明"没报错"，不说明"规则齐全"（会有漏检的规则）；
- 不能证明**生成物正确**：那要 M4 的"产物真能编译" + 对账用例；
- 不能证明**规范一致**：规范本身的歧义要回到 `doc/` / `errata` 裁决；
- **语料 0 error 也不代表正确**（它是历史逆向产物，且语法还在调整）—— 所以它不进判据，只进报告；
- 因此每一轮我都会给「已知未做」清单，**不把没验证的说成验证过的**。

## 9. AI 协作纪律（对你关心的那件事）

| 允许 | 禁止 |
| --- | --- |
| 写用例 / fixture / 样板 / 机械重构（**有快照证明行为不变**） | 在没有反例用例时宣布"支持某语法" |
| 从 `doc/` 提取规则骨架、查 API | 引入 `doc/` 里不存在的概念、造词 |
| 提出方案并**标注不确定项** | 编造跑不通的输出、把"应该可以"写成"已验证" |
| 每轮给回归数据 | 悄悄改语料/基线让测试变绿 |

**跑不通就报跑不通** —— 这条比任何"我很强"的承诺都值钱。
