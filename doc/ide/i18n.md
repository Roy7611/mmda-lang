# Architect 国际化（i18n）

Architect UI 与 MMDA 项目元数据采用 **两层 i18n**，职责分离：

| 层 | 范围 | 存储 | 示例 |
|----|------|------|------|
| **Shell i18n** | 菜单、工作流、面板、按钮 | `apps/architect-ui/src/i18n/locales/*.json` | 「资源管理器」「Codegen Profile」 |
| **Model i18n** | Record / Field / Action 等业务标签 | 元模型 `label`、M语言 注解、将来 `ui/` | `mes.Bom` 显示「物料清单」 |

Shell 文案 **不写入** `.mmda` 项目；业务标签 **不硬编码** 在 Vue 组件中。

## 1. Shell i18n（Vue）

### 1.1 技术栈

- [vue-i18n](https://vue-i18n.intlify.dev/) v10（Composition API，`legacy: false`）
- 入口：`src/i18n/index.ts`，在 `main.ts` 中 `app.use(i18n)`

### 1.2 支持语言

| locale | 说明 |
|--------|------|
| `zh-CN` | 简体中文（默认，与规范文档一致） |
| `en` | English |
| `zh-Hant` | 繁體中文（对齐 Legacy `java-factory` 的 `zh-Hant`） |

浏览器首次访问时：

1. 读取 `localStorage` 键 `mmda-locale`
2. 若无，则按 `navigator.language` 推断（`zh-TW`/`zh-HK` → `zh-Hant`，其余 `zh*` → `zh-CN`，`en*` → `en`）
3. 设置 `<html lang="…">`

### 1.3 切换入口

**视图 → 显示语言**（与颜色主题同一下拉菜单）；偏好持久化到 `mmda-locale`。

Editor Tab 等动态标题支持 `titleKey` 字段，语言切换后自动重译（见 `EditorTab` in `stores/layout.ts`）。

### 1.4 目录结构

```
apps/architect-ui/src/i18n/
├── index.ts           # createI18n、detectLocale、Syncfusion culture 映射
├── composables.ts     # useWorkflowSteps 等
└── locales/
    ├── zh-CN.json
    ├── en.json
    └── zh-Hant.json
```

新增语言：增加 JSON 文件并在 `SUPPORTED_LOCALES` 中注册。

### 1.5 Syncfusion Diagram

Diagram 内置字符串（右键菜单、提示等）需单独加载 culture 包（Phase 2）：

```typescript
import { L10n, setCulture } from '@syncfusion/ej2-base'
import * as zhCN from '@syncfusion/ej2-locale/src/zh-CN.json'

L10n.load(zhCN)
setCulture(localeToSyncfusionCulture(appLocale)) // zh-CN | zh-TW | en-US
```

`localeToSyncfusionCulture()` 已定义于 `src/i18n/index.ts`。Phase 1 演示画布以自定义节点标签为主，可不装 `@syncfusion/ej2-locale`。

### 1.6 Host 嵌入

VS Code / IDEA Webview 与 Tauri 桌面壳 **共用同一 UI 包**；语言偏好存于各 Host 的 `localStorage`（同源策略下独立）。将来 Host 可通过 URL 参数 `?locale=en` 覆盖默认值。

## 2. Model i18n（项目 SSOT）

### 2.1 label

元模型元素（Record、Field、Action、Module 节点等）使用 `label` 作为 **默认显示名**（通常为项目主语言）。详见 [meta-model.md](../meta-model.md)。

多语言扩展（Phase 2+）可选方案：

```yaml
# modules/modules.yaml 示例（草案）
- code: M.01
  label: 生产管理
  labels:
    en: Production
    zh-Hant: 生產管理
```

或在 Lang 中使用注解（与 Codegen / UI 生成对齐）：

```mmda
@Label("物料清单")
@Label(locale = "en", value = "Bill of Materials")
record mes.Bom { ... }
```

**原则**：M语言 / YAML 为 SSOT；UI 按当前 Shell locale 选取 `labels[locale]`，缺省回退 `label`。

### 2.2 manifest 语言元数据（可选）

项目可声明支持的业务语言，供 Architect 校验与 Codegen：

```json
{
  "defaultLocale": "zh-CN",
  "locales": ["zh-CN", "en", "zh-Hant"]
}
```

| 字段 | 说明 |
|------|------|
| `defaultLocale` | 项目主语言；`projectLabel` / 文档默认语言 |
| `locales` | 项目提供的 `label` 翻译集合；Codegen Profile 可据此生成 i18n 资源文件 |

与 Shell locale **独立**：用户 UI 选英文，仍可编辑中文标签为主的 mmda-mes 项目。

### 2.3 Codegen Profile

代码生成配置可声明输出 i18n 格式（Phase 2），例如：

```yaml
i18n:
  format: properties   # properties | json | yaml
  locales: [zh-CN, en]
  outputDir: generated/i18n
```

Legacy [java-factory.md](../legacy/java-factory.md) 中的 `locales: [zh, zh-Hant, en]` 对应此能力的历史形态。

## 3. 与 AI / CLI 的关系

- `mmda validate` 不校验 Shell 文案；可校验 `locales` 与 `labels` 完整性（将来规则）。
- AI 工具读写 `label` 时使用项目 `defaultLocale`；向用户解释时用 Shell 当前语言。
